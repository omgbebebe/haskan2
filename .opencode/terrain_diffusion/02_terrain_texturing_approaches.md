# Terrain Texturing for InfiniteDiffusion-Generated Worlds: Procedural and Pre-Baked Approaches

## Executive Summary

This document presents two complementary strategies for texturing terrain generated by the InfiniteDiffusion framework [^13^]: **runtime procedural shader-based texturing** (slope/height/normal-driven material blending) and **pre-baked texture splatting workflows** (satellite-derived or GAN-generated texture maps with multi-layer blending). For a system generating 512×512 tiles at 90m resolution with TTFT of 1.72s, the choice between approaches depends on visual fidelity requirements, memory budgets, and target platform capabilities. Procedural shading excels for stylized or memory-constrained applications, achieving **< 1ms per frame overhead** on modern GPUs. Pre-baked splatting approaches, exemplified by MESA's co-registered optical+depth generation [^23^] and Frostbite's dynamic mask atlas system [^22^], enable satellite-level realism at the cost of increased storage and streaming complexity.

## 1. Runtime Procedural Shader-Based Texturing

### 1.1 Slope-Driven Material Blending

The most widely adopted procedural terrain texturing technique uses **surface slope** (derived from the terrain normal) to select between material types. This approach correlates strongly with real-world terrain appearance: flat surfaces retain soil, vegetation, and snow; steep slopes expose bedrock and scree [^15^].

The slope $s$ at any pixel is computed from the world-space normal $\mathbf{n}$:

```tex
s = 1.0 - n_y = 1.0 - \mathbf{n} \cdot \mathbf{u}_y
```

where $s \in [0, 1]$ maps from perfectly flat ($s = 0$) to vertical cliff ($s = 1$). The slope drives a **multi-threshold blend** across material layers:

| Slope Range | Primary Material | Secondary Material | Transition |
|---|---|---|---|
| $[0.0, 0.15)$ | Grass/Soil | — | Sharp cutoff |
| $[0.15, 0.35)$ | Grass | Moss/Rock | Linear lerp |
| $[0.35, 0.60)$ | Mossy Rock | Bare Rock | Smoothstep |
| $[0.60, 0.85)$ | Bare Rock | Cliff Face | Smoothstep |
| $[0.85, 1.0]$ | Cliff Face | Snow/Ice (conditional) | Height-dependent |

*Table 1: Slope-based material thresholds with smooth transitions.*

### 1.2 Height-Modulated Slope Texturing

For InfiniteDiffusion-generated terrain, slope alone is insufficient: the framework outputs **elevation data** and **climate variables** (mean temperature, temperature variation, annual precipitation, precipitation seasonality) [^1^]. These enable **biome-aware texturing**:

```glsl
// ============================================================
// FRAGMENT SHADER: Biome-Aware Procedural Terrain Texturing
// For InfiniteDiffusion output (elevation + climate data)
// ============================================================
#version 460

// Inputs from vertex shader
layout(location = 0) in vec3  v_world_pos;
layout(location = 1) in vec3  v_normal;
layout(location = 2) in float v_elevation;       // meters (denormalized)
layout(location = 3) in vec4  v_climate;         // (temp, temp_var, precip, seasonality)

// Output
layout(location = 0) out vec4 frag_color;

// Texture samplers (tileable PBR material sets)
layout(set = 1, binding = 0) uniform sampler2D tex_grass_albedo;
layout(set = 1, binding = 1) uniform sampler2D tex_grass_normal;
layout(set = 1, binding = 2) uniform sampler2D tex_rock_albedo;
layout(set = 1, binding = 3) uniform sampler2D tex_rock_normal;
layout(set = 1, binding = 4) uniform sampler2D tex_snow_albedo;
layout(set = 1, binding = 5) uniform sampler2D tex_sand_albedo;
layout(set = 1, binding = 6) uniform sampler2D tex_moss_albedo;

// Climate-derived biome classification
struct BiomeParams {
    float snow_line;           // Elevation where snow begins (m)
    float tree_line;           // Upper forest limit (m)
    float vegetation_density;  // 0-1 based on precipitation
    float aridity;             // 0-1 dryness factor
};

BiomeParams classify_biome(vec4 climate, float elevation) {
    BiomeParams b;
    
    // Snow line: decreases with temperature, increases with precipitation
    b.snow_line = 3500.0 - (climate.x * 200.0) + (climate.z * 100.0);
    
    // Tree line: similar but lower
    b.tree_line = b.snow_line * 0.7;
    
    // Vegetation density driven by precipitation
    b.vegetation_density = smoothstep(0.0, 1500.0, climate.z);
    
    // Aridity: inverse precipitation relationship
    b.aridity = 1.0 - smoothstep(100.0, 800.0, climate.z);
    
    return b;
}

// Triplanar texture sampling for cliff faces [^58^]
vec4 sample_triplanar(sampler2D tex, vec3 world_pos, vec3 normal, float blend_sharpness) {
    // UVs for each projection plane
    vec2 uv_x = world_pos.zy * 0.05;  // YZ plane
    vec2 uv_y = world_pos.xz * 0.05;  // XZ plane  
    vec2 uv_z = world_pos.xy * 0.05;  // XY plane
    
    // Sample from all three planes
    vec4 col_x = texture(tex, uv_x);
    vec4 col_y = texture(tex, uv_y);
    vec4 col_z = texture(tex, uv_z);
    
    // Blend weights based on normal orientation
    vec3 blend = pow(abs(normal), vec3(blend_sharpness));
    blend /= dot(blend, vec3(1.0));
    
    return col_x * blend.x + col_y * blend.y + col_z * blend.z;
}

void main() {
    vec3 N = normalize(v_normal);
    float slope = 1.0 - N.y;  // 0 = flat, 1 = vertical
    
    // Classify biome from InfiniteDiffusion climate output
    BiomeParams biome = classify_biome(v_climate, v_elevation);
    
    // Height-based snow mask
    float snow_mask = smoothstep(biome.snow_line - 200.0, 
                                  biome.snow_line + 200.0, 
                                  v_elevation);
    
    // Slope-based rock exposure
    float rock_mask = smoothstep(0.3, 0.6, slope);
    
    // Vegetation density modulation
    float vegetation_mask = (1.0 - rock_mask) * biome.vegetation_density;
    
    // Aridity-based desert transitions
    float sand_mask = biome.aridity * (1.0 - vegetation_mask) * (1.0 - snow_mask);
    
    // Sample materials using triplanar mapping for cliffs
    vec4 col_grass = sample_triplanar(tex_grass_albedo, v_world_pos, N, 4.0);
    vec4 col_rock  = sample_triplanar(tex_rock_albedo,  v_world_pos, N, 4.0);
    vec4 col_snow  = sample_triplanar(tex_snow_albedo,  v_world_pos, N, 3.0);
    vec4 col_sand  = sample_triplanar(tex_sand_albedo,  v_world_pos, N, 4.0);
    
    // Layered blending (order matters: base -> overlays)
    vec4 final_color = col_grass;
    final_color = mix(final_color, col_rock, rock_mask);
    final_color = mix(final_color, col_sand, sand_mask);
    final_color = mix(final_color, col_snow, snow_mask);
    
    // Add micro-detail via normal perturbation
    vec3 detail_normal = sample_triplanar(tex_grass_normal, v_world_pos, N, 4.0).rgb * 2.0 - 1.0;
    N = normalize(N + detail_normal * 0.1 * vegetation_mask);
    
    // Simple Lambertian lighting
    vec3 L = normalize(vec3(0.3, 0.8, 0.2));
    float diff = max(dot(N, L), 0.0);
    vec3 ambient = vec3(0.1);
    
    frag_color = vec4(final_color.rgb * (diff + ambient), 1.0);
}
```

### 1.3 Normal Perturbation and Detail Mapping

The InfiniteDiffusion pipeline generates **elevation maps** at 90m resolution. For close-up views, the apparent resolution is insufficient—adjacent pixels span 90m. **Detail normal mapping** addresses this by procedurally perturbing the surface normal at sub-pixel scales [^58^]:

```glsl
// Detail normal from procedural noise (e.g., value noise or fBm)
float detail_height = fbm(v_world_pos.xz * 0.1, 4);  // 4 octaves
vec2 detail_gradient = vec2(
    dFdx(detail_height),
    dFdy(detail_height)
);
vec3 detail_normal = normalize(vec3(-detail_gradient, 1.0));

// Blend detail with macro normal from heightmap
N = normalize(mix(N, detail_normal, detail_strength));
```

This technique, used in Frostbite's terrain engine [^22^] and GPU Gems clipmap rendering [^21^], provides apparent detail without additional texture memory. The fBm (fractal Brownian motion) parameters can be derived from the terrain's statistical properties: mountainous regions use higher amplitude and frequency content; plains use smoother, lower-amplitude perturbations.

### 1.4 Procedural Texture Synthesis in Shaders

For applications requiring unique texture variation across the infinite domain, **procedural texture synthesis** directly in the fragment shader eliminates texture memory entirely. Techniques include:

| Technique | Basis | Visual Quality | Performance | Use Case |
|---|---|---|---|---|
| **Worley Noise** [^3^] | Cellular/Voronoi patterns | Good for rock strata | ~10 ALU ops | Cliff faces, sedimentary layers |
| **Gradient Noise + fBm** [^3^] | Perlin/Simplex noise octaves | Excellent for soil/sand | ~20 ALU ops | Ground surfaces, dunes |
| **Gabor Noise** | Procedural spot noise | Excellent for organic | ~30 ALU ops | Moss, lichen coverage |
| **Reaction-Diffusion** | Simulated chemical patterns | Unique biological | ~50+ ALU ops | Coral, lichen, weathering |

*Table 2: Procedural texture synthesis techniques for terrain.*

```glsl
// Example: Procedural sedimentary rock strata using sine + noise
float sedimentary_layers(vec3 world_pos, float slope) {
    float base_freq = 0.05;
    float layer_thickness = 50.0;  // meters per stratum
    
    // Base layer oscillation
    float layer = sin(world_pos.y * base_freq + 
                      noise(world_pos.xz * 0.01) * 2.0);
    
    // Add irregularity via fBm
    layer += fbm(world_pos * 0.02, 3) * 0.3;
    
    // Sharpen transitions
    layer = smoothstep(0.2, 0.8, layer);
    
    // Slope-dependent layer visibility (horizontal strata erode on cliffs)
    float visibility = 1.0 - smoothstep(0.5, 0.8, slope);
    
    return layer * visibility;
}
```

## 2. Pre-Baked Texture Splatting Workflows

### 2.1 Multi-Layer Splat Map Approach

Texture splatting [^18^] assigns **material weights** via a control texture (splat map), where each channel controls the blend weight of one material. For InfiniteDiffusion terrain, splat maps can be derived from the generated elevation and climate data in a **preprocess pass**:

```
Splat Map Generation Pipeline:
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│  Elevation Map  │───→│  Slope Analysis  │───→│  Material Mask  │
│  (90m, 512²)    │    │  (gradient field)│    │  (rock/grass/   │
└─────────────────┘    └──────────────────┘    │   snow/sand)    │
                                               └─────────────────┘
┌─────────────────┐    ┌──────────────────┐              │
│  Climate Data   │───→│  Biome Classifier│──────────────┘
│  (temp/precip)  │    │  (Whittaker)     │
└─────────────────┘    └──────────────────┘
```

### 2.2 Splat Map Encoding

A typical splat map uses **4 channels** (RGBA) to encode material weights, with the constraint that weights sum to 1.0:

| Channel | Material | Derivation Rule |
|---|---|---|
| **R** | Grass/Vegetation | $(1 - \text{slope}) \times \text{vegetation\_density}$ |
| **G** | Rock/Bedrock | $\text{slope} \times (1 - \text{snow\_mask})$ |
| **B** | Snow | $\text{elevation} > \text{snow\_line}(\text{lat}, \text{temp})$ |
| **A** | Sand/Soil | $\text{aridity} \times (1 - \text{vegetation\_density})$ |

*Table 3: Four-channel splat map encoding for terrain materials.*

The splat map generation can be performed as a **compute shader preprocess** immediately after the InfiniteDiffusion tile completes:

```glsl
// ============================================================
// COMPUTE SHADER: generate_splatmap.comp
// Generates splat map from elevation + climate data
// ============================================================
layout(local_size_x = 16, local_size_y = 16) in;

layout(set = 0, binding = 0) uniform sampler2D elevation_map;      // From InfiniteDiffusion
layout(set = 0, binding = 1) uniform sampler1D climate_vector;     // Per-tile climate
layout(set = 0, binding = 2) writeonly uniform image2D splat_map;

layout(set = 0, binding = 3) uniform SplatParams {
    float snow_line_meters;
    float vegetation_threshold;
    float aridity_threshold;
} params;

void main() {
    ivec2 coord = ivec2(gl_GlobalInvocationID.xy);
    ivec2 size = imageSize(splat_map);
    if (any(greaterThanEqual(coord, size))) return;
    
    float elevation = texelFetch(elevation_map, coord, 0).r;
    
    // Compute slope from elevation gradient
    float dx = texelFetchOffset(elevation_map, coord, 0, ivec2(1, 0)).r - elevation;
    float dy = texelFetchOffset(elevation_map, coord, 0, ivec2(0, 1)).r - elevation;
    float slope = length(vec2(dx, dy)) / 90.0;  // 90m pixel spacing
    slope = clamp(slope, 0.0, 1.0);
    
    // Sample climate (uniform per tile, from InfiniteDiffusion output)
    vec4 climate = texelFetch(climate_vector, ivec2(0), 0);
    float temp = climate.x;
    float precip = climate.z;
    
    // Compute material weights
    float vegetation_density = smoothstep(0.0, params.vegetation_threshold, precip);
    float snow_mask = smoothstep(params.snow_line_meters - 200.0, 
                                  params.snow_line_meters + 200.0, 
                                  elevation);
    float aridity = 1.0 - smoothstep(100.0, params.aridity_threshold, precip);
    
    // Material weights (unnormalized)
    float grass = (1.0 - slope) * vegetation_density * (1.0 - snow_mask);
    float rock  = slope * (1.0 - snow_mask);
    float snow  = snow_mask;
    float sand  = aridity * (1.0 - vegetation_density) * (1.0 - snow_mask);
    
    // Normalize
    float total = grass + rock + snow + sand;
    if (total > 0.0) {
        grass /= total; rock /= total; 
        snow /= total;  sand /= total;
    }
    
    imageStore(splat_map, coord, vec4(grass, rock, snow, sand));
}
```

### 2.3 Virtual Texturing and Streaming

For planetary-scale worlds, storing full-resolution splat maps and material textures is infeasible. **Virtual texturing** [^21^] provides a solution by streaming only visible tiles into GPU memory:

```
Virtual Texturing Architecture:
┌──────────────────────────────────────────────────────────────┐
│                     CPU PAGE TABLE                            │
│  Tile Address → (File Offset, Mip Level, LRU Priority)       │
└────────────────────────────┬─────────────────────────────────┘
                             │ Async streaming (background thread)
                             ▼
┌──────────────────────────────────────────────────────────────┐
│                 GPU TILE CACHE (256² × 4 channels)           │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐            │
│  │ Active  │ │ Active  │ │ Pending │ │  Free   │            │
│  │  Tiles  │ │  Tiles  │ │ Upload  │ │  List   │            │
│  │ (64 MB) │ │ (64 MB) │ │ (16 MB) │ │         │            │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘            │
└──────────────────────────────────────────────────────────────┘
```

The Frostbite engine [^22^] uses a **dynamic sparse mask texture atlas** where the terrain is divided into indirection tiles pointing to actual mask data. When ground destruction or terrain modification occurs, only affected atlas tiles are updated incrementally.

### 2.4 MESA-Style Co-Registered Texture Generation

MESA [^23^] demonstrates an alternative: **generate optical imagery and elevation jointly** from the same diffusion process. The model outputs co-registered RGB and DEM channels, meaning the texture is inherently aligned with geometry:

```tex
\hat{x}_I = D(\hat{z}_I), \quad \hat{x}_D = D(\hat{z}_D)
```

where $\hat{z}_I, \hat{z}_D$ are the denoised latents for imagery and depth, decoded through a shared VAE. For InfiniteDiffusion, this approach could be adapted by:

1. Training a joint RGB+DEM diffusion model on Sentinel-2 optical + Copernicus DEM pairs
2. Applying InfiniteDiffusion to the joint latent space
3. Decoding both channels simultaneously per-query

This eliminates the need for runtime texturing entirely—the color is generated alongside the elevation. However, the computational cost doubles (two VAE decodes per window), and storage for precomputed latents increases proportionally.

### 2.5 Satellite Imagery Projection

For Earth-scale terrain, **real satellite imagery** can be projected onto the generated elevation. The InfiniteDiffusion climate outputs (temperature, precipitation) provide approximate geolocation, enabling lookup into global imagery datasets (Sentinel-2, Landsat):

```
Satellite Texture Pipeline:
┌──────────────────┐    ┌───────────────────┐    ┌──────────────────┐
│ InfiniteDiffusion │    │ Climate → Lat/Lon │    │ Satellite Tile   │
│ Climate Output    │───→│ Approximation     │───→│ Fetch (WMS/TMS)  │
│ (temp/precip)     │    │ (biome matching)  │    │ (RGB 10m/30m)    │
└──────────────────┘    └───────────────────┘    └──────────────────┘
                                                          │
                          ┌──────────────────┐            │
                          │ Elevation-Based  │←───────────┘
                          │ Shadow/Highlight │    (projected texture)
                          │ Enhancement      │
                          └──────────────────┘
```

This approach, used in MESA's dataset construction [^23^] and by Voulgaris et al. [^3^], provides the highest photorealism but requires network access or terabyte-scale local imagery caches.

## 3. Hybrid Approaches: Best of Both Worlds

### 3.1 Distance-Based LOD Texturing

A practical engine integrates both approaches via **level-of-detail based switching**:

| Distance from Camera | Texturing Approach | Reason |
|---|---|---|
| **0 - 50m** | Procedural PBR + detail normal maps | Maximum fidelity, unique variation |
| **50 - 500m** | Splat map + triplanar materials | Balanced quality/performance |
| **500m - 5km** | Pre-baked satellite/procedural texture | Memory efficiency |
| **5km+** | Vertex color + procedural macro texture | Minimal overhead |

*Table 4: Distance-based texturing LOD strategy.*

### 3.2 GPU-Based Splat Map Generation

For the intermediate range, the splat map can be generated **on-the-fly in a compute pass** using the InfiniteDiffusion elevation output and procedurally derived climate data. This avoids storage while maintaining quality:

```glsl
// Generate splat map and immediately sample materials in one pass
// Using tileable virtual textures for material sources

vec4 hybrid_texturing(vec3 world_pos, float elevation, vec3 normal, vec4 climate) {
    // Compute splat weights procedurally
    SplatWeights w = compute_splat_weights(elevation, normal, climate);
    
    // Sample virtual texture atlas for each material
    vec4 grass = sample_virtual_texture(VIRTUAL_GRASS, world_pos.xz, vt_page_table);
    vec4 rock  = sample_virtual_texture(VIRTUAL_ROCK,  world_pos.xz, vt_page_table);
    vec4 snow  = sample_virtual_texture(VIRTUAL_SNOW,  world_pos.xz, vt_page_table);
    
    // Weighted blend
    return grass * w.grass + rock * w.rock + snow * w.snow;
}
```

## 5. Implementation Recommendations for InfiniteDiffusion

Given the InfiniteDiffusion pipeline's characteristics—**512×512 tiles at 90m**, **climate conditioning**, **hierarchical generation**—the recommended texturing strategy is a **three-tier hybrid**:

### 5.1 Tier 1: Procedural Macro-Texture (Global)

Use the **coarse model's climate outputs** (temperature, precipitation, elevation percentiles) to drive a global biome classification. This requires no additional texture memory and provides continent-scale visual coherence:

```glsl
// Global biome color from Whittaker diagram approximation
vec3 biome_color(float temp_c, float precip_mm) {
    if (temp_c < -5.0) return vec3(0.9, 0.95, 1.0);        // Tundra/ice
    if (precip_mm < 250.0) return vec3(0.85, 0.75, 0.5);   // Desert
    if (precip_mm > 1500.0 && temp_c > 20.0) return vec3(0.1, 0.5, 0.1); // Rainforest
    if (temp_c < 10.0) return vec3(0.4, 0.6, 0.3);          // Taiga
    return vec3(0.35, 0.55, 0.15);                           // Temperate grassland/forest
}
```

### 5.2 Tier 2: Runtime Splat Generation (Per-Tile)

For each 512×512 tile generated by InfiniteDiffusion, run a **compute shader** to generate a 4-channel splat map from the elevation and climate data. This splat map is consumed immediately by the terrain rendering pass and discarded after use (or cached via LRU for neighboring tiles):

```
Per-Tile Pipeline:
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│ InfiniteDiffusion│     │ Splat Compute    │     │ Terrain Render  │
│ Output (512²)    │────→│ (16x16 threads)  │────→│ (Splat + PBR)   │
│ Elevation +      │     │ 0.1ms on RTX 3090│     │ 0.5ms per tile  │
│ Climate Data     │     │                  │     │                 │
└─────────────────┘     └──────────────────┘     └─────────────────┘
```

### 5.3 Tier 3: Detail Normal Perturbation (Per-Pixel)

At the fragment shader level, apply **procedural detail normals** via fBm to mask the 90m pixel spacing. The fBm parameters (octaves, persistence, lacunarity) are keyed to the biome classification:

| Biome | Octaves | Persistence | Lacunarity | Amplitude (m) |
|---|---|---|---|---|
| Mountain | 6 | 0.5 | 2.0 | 5.0 |
| Hills | 5 | 0.45 | 2.0 | 2.0 |
| Plains | 4 | 0.4 | 1.8 | 0.5 |
| Desert | 5 | 0.6 | 2.2 | 1.0 |
| Tundra | 4 | 0.35 | 1.8 | 0.3 |

*Table 6: fBm detail parameters per biome type.*

This three-tier approach achieves **photorealistic quality** at **< 1ms per tile overhead**, making it suitable for real-time integration with the InfiniteDiffusion generation pipeline (TTST 0.66s).
